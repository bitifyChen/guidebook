# 前台主視覺：圖片驅動的旅程伴侶

狀態：2026-10-02 已確認方向；本文件定義後續設計與驗收，不代表畫面已實作。動態另見 [前台動態規範](frontend-motion.md)。

## 已確認的體驗

採用「平衡型」：大照片建立旅程氣氛，同一個首屏仍能辨識下一站、時間與主要操作。清楚的行程結構結合目的地照片的氛圍，讓使用者一眼知道自己在哪段旅程、接下來做什麼。

以 Awwwards、Webby Awards、FWA 等作品的細節完成度作為追求，實際驗收依據是閱讀、構圖、操作連續性與真實裝置表現；不宣稱符合任何獎項的官方評分或保證得獎。

## 保留的產品基礎

- 保留目前路由、導覽、功能入口、資料流、登入與旅程上下文；視覺更新不得默默改變操作流程。
- 維持 Vue、既有元件、Pinia、Element Plus、Tailwind 與 Lucide 的使用慣例，優先沿用既有能力。
- 手機畫布最大 `28rem`，桌機置中；固定導覽與 Drawer 受相同畫布限制，處理 safe-area、鍵盤與底部操作空間。
- 橘色維持主要操作與目前狀態；slate 文字、白色內容表面。照片可帶入自然色彩，介面不另增競爭主色。藍、綠、紅保留功能語意。
- Liquid Glass 僅限 `src/layouts/default.vue` navbar 與 `src/pages/Itinerary.vue` 日期選擇背景；文字與圖示不扭曲。卡片、表單、Drawer 與後台不得擴用。

## 首屏與頁面分工

| 區域 | 圖片與資訊角色 | 必須保留的可用性 |
| --- | --- | --- |
| 首頁 | 今日旅程或下一站的相關照片為主角，搭配簡潔旅程標題與天氣摘要 | 下一站、時間與主要行動在一般手機首屏可辨識；其他既有功能仍可到達 |
| 行程 | 目前或重要景點使用較大照片，其餘採縮圖與緊湊資訊列 | 日期選擇、時間順序、交通與必要狀態容易掃描 |
| 景點詳情 | 延續來源卡片的同一張照片，內容在穩定、可讀的表面展開 | 返回後保留日期、捲動位置與使用者上下文 |
| 位置 | 地圖與定位狀態為主角 | pan、zoom、成員、導航與定位錯誤處理完整 |
| 錢包、設定、工具 | 以資料與操作為主，不為圖片驅動而增加無關大圖 | 輸入、金額、狀態與確認操作保持清楚 |

首頁照片約占首屏四成可作原型起點，不是固定比例。先以 390×844 驗證；遇到長名稱、文字放大或短螢幕，讓圖片縮小或資訊自然延伸，不壓縮文字或藏掉操作來維持比例。

## 照片與排版

- 使用與實際目的地相關、可合法使用的照片；參考圖只作設計討論，不直接視為正式素材。不得把虛構景點影像呈現為實景。
- 優先使用現有行程 `cover` 與 `images`。目前已檢視的旅程資料未見獨立封面欄位；新增旅程封面或焦點資料屬後續獨立範圍，不在視覺改版中暗加。
- 同一景點在卡片與詳情盡量沿用同圖及主體位置。圖片容器可改比例，圖片以裁切適應，不拉伸人物、建築或文字。
- 每頁只建立一個主要視覺焦點。不要讓每張卡片都同樣巨大、每一區都套陰影，或大量卡片再包卡片。
- 延續既有 sans 與繁體中文；標題、時間、狀態、操作的層級比裝飾英文更重要。圓角沿用既有 16～32px 語彙並控制種類。
- 圖上文字只保留短標題或少量摘要，使用穩定遮罩提供對比；必要資訊與長文放在實心表面。正常文字對比至少 4.5:1，大字至少 3:1。
- 控制項至少 44×44px，焦點清楚，圖示有可理解名稱；不以顏色或照片單獨傳達狀態。

## 圖片狀態與效能

圖片容器預留尺寸，載入不推動文字與按鈕。首屏主圖優先載入，折疊下方圖片延遲載入並依顯示尺寸提供適當資源；不得預載整趟旅程相簿。

缺圖、失敗與離線時使用中性實心底與景點名稱，仍顯示時間與操作。可用快取圖時保留它，不以破圖取代內容。切換照片失敗保留舊圖及可重試狀態，不阻塞導覽。具資訊意義的照片提供替代文字，純裝飾且與旁文重複時使用空替代文字。

## 後續實作順序與驗收

先製作「首頁 → 景點詳情 → 返回」的小範圍原型，確認照片比例、首屏資訊及動態節奏，再逐步延伸到行程與相簿。這是後續實作順序，本次僅建立文件。

- 在 390×844、430×932、較窄手機與桌機檢查畫布；文字放大到 200% 時資訊及操作仍可取得。
- 用長繁體中文名稱、無照片、慢網、離線、載入失敗與空行程檢查，不能只驗收理想資料。
- 確認首屏能辨識下一站與主要行動，照片未壓過實際任務。
- 確認 navbar、日期與 Drawer 不遮擋內容；地圖與表單流程仍可操作。
- 動態須通過 [動態驗收](frontend-motion.md#驗收情境)，並在真實手機檢查觸控、返回與捲動。
